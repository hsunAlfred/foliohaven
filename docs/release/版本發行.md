# 版本取得、驗證與打包

Foliohaven 每個正式版本提供可修改的完整來源、使用文件、測試及相同來源的 Docker 建置方式。日常架站從 [README](../../README.md) 開始；升級自己的網站先讀[版本更新與備份](../blog/版本更新與備份.md)。

## 取得正式版本

公開入口為 [hsunAlfred/foliohaven](https://github.com/hsunAlfred/foliohaven)。`main` 提供公開來源，`v版本號` tag 固定各版本的提交；GitHub Release 提供 CHANGELOG 與下載附件。

日常使用請選擇正式版本；GitHub Release 標記為 **Pre-release** 的是預覽版本，供試用與測試。

從 [Releases](https://github.com/hsunAlfred/foliohaven/releases) 下載同一版本的：

- `foliohaven-版本-source.tar.gz`
- `SHA256SUMS`

在兩個檔案所在目錄執行：

```bash
sha256sum --check SHA256SUMS
```

確認顯示 OK，再解壓到新的空目錄：

```bash
mkdir foliohaven-1.0.0
tar --no-same-owner --same-permissions -xzf foliohaven-1.0.0-source.tar.gz -C foliohaven-1.0.0
cd foliohaven-1.0.0
```

依根目錄 README 選擇 Docker 或原生 Linux。GitHub 自動產生的 Source code ZIP／tar 對應 tag 快照；正式發行附件另經逐檔清單與解壓驗證，請優先使用附有 SHA256SUMS 的來源包。

## 版本包含什麼

- 完整程式、固定套件與工具設定、Dockerfile 與 Compose。
- 中性首頁、五篇教學文章及可替換的網站設定與示範媒體。
- README、AGENTS、CHANGELOG、MIT LICENSE、操作指南及資料契約。
- 單元、整合、三瀏覽器測試及隔離 fixture，可驗證自己的程式修改。
- 不依賴特定 AI 工具的 Dev Container。

來源包不含已安裝依賴、根網站 dist、Docker image、工作／部署紀錄或實際憑證。公開網站只需正式 Build 產生的完整 `dist/`；Studio 與管理 API 不部署到公開網站。

`release-info.json` 記錄產品、版本、格式與逐檔路徑、大小、權限、SHA-256。Git 歷史、工作紀錄及復原資料由各網站自行保存。

## 自訂與更新

Foliohaven 允許直接修改 React／Astro、樣式及工具。新版本不能整包覆蓋自己的程式、文章或媒體；請在副本整合差異，再測試與 Build。0.3.0 保存的新欄位不能直接交給舊版 strict schema，降版需還原升級前完整備份。

Docker 每版都從同一來源重新建置；沒有預設的外部 image registry。只取得 image 不能代替可修改的來源專案與 Compose。

問題回報與 PR 政策見 [CONTRIBUTING](../../CONTRIBUTING.md)。

## 從固定來源打包

需要整理自己的來源包時，使用乾淨且已提交的 Git 來源，或沒有 `.git/` 的來源目錄。以固定 Node.js／pnpm 的 Linux 環境執行，Docker 工具鏈也可使用相同命令：

```bash
pnpm release:package --output /tmp/foliohaven-release
```

目的地必須是新的或空的目錄；工具不覆蓋既有資料。Git 來源使用固定 HEAD 的匯出快照，未提交修改會被拒絕；無 Git 來源使用目前檔案。

輸出為：

```text
/tmp/foliohaven-release/
├── source/
├── foliohaven-1.0.0-source.tar.gz
└── SHA256SUMS
```

工具依 `release/manifest.json` 匯出來源，映射中性 Dev Container 與公開 Check workflow，再建立清單與 tar。一般檔名排除規則無法辨識正文或 JSON 中誤填的敏感資訊；正式公開前，必須核對作者資料、示例、授權及對外設定。

從最終固定提交產生正式附件，不沿用不同來源的候選包。校驗壓縮檔並解壓到另一個空目錄，核對內容、權限、版本與清單。Git archive 與一般 checkout 的群組寫入權限可能不同，每份清單須對應自己的實際封裝來源，並保留可執行檔權限。

## 發行品質檢查

正式交付前完成 `pnpm verify` 與相同提交對應的 CI。CI 驗證公開來源、工具鏈、完整檢查與獨立 Docker；CI 通過不會自動建立 tag 或發布 Release。

有 Docker 的非 root 主機可在固定來源執行：

```bash
SITE_PORT=14321 STUDIO_PORT=15173 PREVIEW_PORT=14322 bash scripts/check-release-docker.sh
```

這是隔離發行驗收，會建立自己的副本與 Docker project，檢查首次啟動、文章與媒體操作、image 重建資料保存、修復模式及不連雲端的 Cloudflare dry-run。它不是一般使用者的啟動前置工作，也不應停止日常作者環境。

另外核對 Docker verify target、Linux 原生安裝、無 Git 下載包啟動、Studio 保存與重讀、來源／成功網站預覽、正式 Build 與修改保存。記錄實際平台，未執行的系統或實機不宣稱通過。

正式 tag 與附件發布後保持固定；修正使用新版本，不移動舊 tag 或覆蓋已發布附件。發布後從實際 Release 下載附件，再校驗、解壓與核對清單，才完成交付。
