# 版型與樣式調整

首次架站時，先完成固定頁面與共用文章版型，再開始管理自己的文章。這些修改都在原始碼中完成；可自行操作，也可以交給讀過 [AGENTS.md](../../AGENTS.md) 的 AI Agent。Studio 管理文章與設定，不會取代固定頁面及版型的程式編輯。

人與 AI Agent 修改外觀前，先讀[網站開發與品質標準](網站開發與品質標準.md)。架構、媒體載入、布局、可及性、SEO 與效能目標共用該標準；本文說明版型修改位置及操作，不另維護一份品質清單。

## 1. 先找到要修改的位置

| 需求                                | 主要來源                                                                                          |
| ----------------------------------- | ------------------------------------------------------------------------------------------------- |
| 首頁文字、區塊及排列                | `packages/ui/src/pages/home/HomePage.tsx`                                                         |
| FAQ、About 等新固定頁               | 依[一般獨立頁面建立流程](一般獨立頁面建立流程.md)建立 React、公開 export、Astro Entry 與 registry |
| 所有文章共用的結構                  | `packages/ui/src/article/ArticlePage.tsx`                                                         |
| 文章目錄與共用日期呈現              | `packages/ui/src/article/TableOfContents.tsx`、`packages/ui/src/components/ArticleDate.tsx`       |
| Header、Footer、導覽及文章卡片      | `packages/ui/src/components/`                                                                     |
| 字型、顏色、間距、欄寬及響應式樣式  | `packages/ui/src/styles/index.css`                                                                |
| HTML Document 與共用 Head           | `site/src/layouts/BaseLayout.astro`、`site/src/components/SeoHead.astro`                          |
| 網站名稱、作者、導覽、全站 SEO 預設 | Studio「全站設定」，對應 `content/site.json`                                                      |

首頁讀取網站設定及 Core 的文章集合；修改首頁元件即可改版，不必逐篇修改文章。`ArticlePage` 同時供公開文章與 Studio 即時預覽使用，調整它會影響所有文章。文章導言與列表摘要使用 Core 的有效描述，延伸閱讀使用同一份文章 ViewModel；`.article-body` 是 HTML 正文所在區塊，可在共用 CSS 調整標題、段落、表格、圖片與影片的呈現。

不要直接編輯 `packages/ui/dist/`、`site/dist/` 或根 `dist/`。共用 CSS 由來源同步到公開 `@foliohaven/ui/styles.css`；套件使用公開 export，不跨套件讀取 `src/`。

## 2. 依序完成網站外觀

修改共用版型時沿用既有圖片與文章元件，確認實際欄寬與 `sizes`、首屏圖優先序及增強前後預留空間；現有預設不會自動推導客製 CSS 的欄寬。閱讀位置、程式碼與目錄接線見[跨平台閱讀與版型整合 Memo](跨平台閱讀與版型整合Memo.md)。

1. 依 [README](../../README.md) 選擇 Docker 或原生方式啟動。Docker 可直接編輯主機檔案，或用 `docker compose exec app bash` 進入容器工作。
2. 保存好目前未完成的編輯，再在 Studio「工作區」切到 IDE 模式；避免 IDE／AI 與 Studio 同時保存設定或文章。
3. 調整首頁；需要 FAQ、About 等頁面時，依固定頁流程一併完成路由、SEO、導覽與媒體登錄。
4. 調整 Header／Footer、共用 CSS 及文章版型。先用範例文章檢查長標題、各級標題、目錄、表格、圖片、影片及小螢幕，避免只依短段落決定排版。
5. 完成程式及檔案編輯後，切回 Studio 並重新讀取資料，設定網站、作者、正式網址、導覽及 SEO 預設。也可留在 IDE 模式，依相同 Schema 修改 JSON。
6. 在 `4321` 檢查固定頁與已保存文章。Studio 的裝置預覽用來檢查文章；固定頁使用瀏覽器的響應式檢視工具。

新字型、圖示或其他資源需有適用授權。頁面及共用元件使用的受管媒體，依固定頁流程登錄 `mediaRefs`；不要直接引用原始媒體目錄或本機預覽 API。

## 3. 檢查並建立完整網站

修改 React、TypeScript 或固定頁登錄後，執行：

```bash
pnpm typecheck
pnpm validate:content
pnpm build
```

Docker 在容器內執行，或在主機為各命令加 `docker compose exec app`。依實際變更再執行相關測試；修改資料規則、保存或建置流程時用 `pnpm verify` 做完整驗證。整合及完整驗證需先保存並停止作者服務，釋放固定連接埠；Docker 依 README 使用一次性驗證容器，不能直接在活動中的 app 內跑完整驗證。

成功後在 `4322` 檢查固定頁、文章、分類、Tag、導覽及媒體，再交付完整 `dist/`。若使用 `pnpm dev` 而不是 `pnpm start`，另開終端執行 `pnpm preview`；已由 Docker app 或 `pnpm start` 提供 `4322` 時不要重複啟動。

主要內容必須在停用瀏覽器 JavaScript 時仍可閱讀。SEO、URL、TOC、分頁等規則由 Core 管理；改外觀時保留這些資料契約，不在 React 或 Astro 另做一套計算。

交付時依[網站開發與品質標準](網站開發與品質標準.md#依修改範圍選擇檢查)選擇受影響代表頁，在 `4322` 初驗並記錄實測及未驗範圍；共用樣式、字型或互動改動另依該標準手動量測，既有測試通過不等於 PageSpeed 已達標。

之後依[新增文章流程](新增文章流程.md)新增 HTML／JSON 文章，就會套用已決定的共用版型。需要改版時回到上述來源調整，成功 Build 後再更新公開網站。
