# SEO 設定與繼承

本指南供作者與 AI Agent 共用，集中說明 Foliohaven 的 SEO 設定位置、逐欄繼承與確認方式。一般發文先填好標題、摘要與分類，按需要選擇圖片；需要特殊呈現時再覆寫 SEO。新增文章的完整步驟見[新增文章流程](新增文章流程.md)。

系統統一產生技術輸出，作者決定頁面目的、標題、摘要與內容是否準確有用。版面、媒體與實頁檢查依[網站開發與品質標準](網站開發與品質標準.md)。

## 設定入口與使用順序

| 層次     | Studio 入口                          | 用途                                       |
| -------- | ------------------------------------ | ------------------------------------------ |
| 全域     | 全站設定 → SEO 與社群分享 → 全域預設 | 設定網站共用的標題模板、描述、索引與分享圖 |
| 頁面類型 | 同區的頁面類型預設                   | 為文章、分類等同類頁面建立共同策略         |
| 單筆     | 文章設定，或分類與 Tag 的編輯表單    | 只覆寫這篇文章、這個分類或 Tag 的特殊需求  |

先設定全域，再檢查需要的頁型，日常只調整有特殊需求的單筆。全站設定完成後按「保存全站設定」；文章、分類與 Tag 各自在自己的表單保存。

透過 IDE／Agent 直接修改來源前，先在 Studio「工作區」切到 IDE 模式；保留作者既有的明確覆寫，完成檢查後再切回 Studio 並重新讀取。查看生效結果不會自行把繼承改成固定值。

## 每個欄位獨立繼承

標題、描述、索引與分享圖，各自依「單筆覆寫 → 頁型預設 → 全域設定」解析。只覆寫標題時，其餘三個欄位繼續依原策略取值；不是整組一起覆蓋。

| 欄位             | 全域／頁型策略                             | 單筆操作                                     |
| ---------------- | ------------------------------------------ | -------------------------------------------- |
| SEO Title        | 使用標題模板，頁型可繼承或另設模板         | 留白繼承；填入時使用完整標題                 |
| Meta Description | 頁型可繼承、自訂或使用該類型的內容描述     | 留白繼承，填入時明確覆寫                     |
| Indexing         | 全域允許／不允許；頁型可繼承或覆寫         | 選繼承、允許索引或不允許索引                 |
| OG Image         | 頁型可繼承、指定或不使用；文章另可用精選圖 | 「分享圖片設定」選繼承、指定圖片或不使用圖片 |

標題模板只支援 `{title}` 與 `{siteName}`，例如 `{title} | {siteName}`。單筆 SEO Title 是完整文案，不再套一次模板；分類／Tag 第二頁起另加頁碼。

單筆 SEO Title、Meta Description 與 Indexing 使用 `null` 表示繼承；頁型的標題模板與索引也以 `null` 繼承。頁型描述改用 `descriptionSource` 選擇 `inherit`、`custom` 或 `content`，圖片使用 `imageSource` 策略；切回繼承後，未使用的自訂值可能仍保留，但不參與解析，不可只把值清空而忽略策略。

`false` 是不允許索引，圖片 `none` 是不使用，兩者都不是未設定。全域 Indexing 是回退值，頁型或單筆明確允許索引時可優先於全域 `false`；404 等強制規則則不接受這類覆寫。

這是 SEO 的逐欄三層設定。網站名稱、作者、導覽、首頁精選、分頁、圖示等各有自己的設定；X／Twitter Site 與首頁 Google 驗證也只設全域。

## 八種頁型與內容來源

| 頁型           | 適用頁面         | 可用的內容來源             |
| -------------- | ---------------- | -------------------------- |
| 首頁           | `/`              | 網站描述                   |
| 文章頁         | 各篇文章         | 文章摘要、文章精選圖片     |
| 文章總覽／搜尋 | `/articles/`     | 使用全域或自訂描述與分享圖 |
| 分類總覽       | `/category/`     | 使用全域或自訂描述與分享圖 |
| 分類頁         | 分類與其靜態分頁 | 分類描述                   |
| Tag 總覽       | `/tag/`          | 使用全域或自訂描述與分享圖 |
| Tag 頁         | Tag 與其靜態分頁 | Tag 描述                   |
| 404            | 找不到頁面       | 描述可調整，固定不允許索引 |

文章頁型預設用摘要與精選圖，分類／Tag 預設用自己的描述。選用內容描述但內容留白時，回退全域描述；文章使用精選圖但該篇沒有圖片時，回退全域分享圖。頁型或單筆選「不使用圖片」會停止沿用上層圖片；全域未設圖片也可合法沒有分享圖。

自訂 About 等固定頁的單頁 SEO 由 `site/src/fixed-pages.ts` 維護，未覆寫時使用全域預設；既有首頁與總覽先套用對應頁型。固定頁沒有 Studio 單筆編輯表單，新增流程見[一般獨立頁面建立流程](一般獨立頁面建立流程.md)。

## 標題、摘要與搜尋描述

| 內容                  | 使用位置                                                          |
| --------------------- | ----------------------------------------------------------------- |
| 文章標題              | H1、卡片、列表及延伸閱讀標題                                      |
| SEO Title             | HTML title、Open Graph 與 Twitter 標題                            |
| 文章摘要 `excerpt`    | 列表、搜尋、延伸閱讀、RSS 單篇及 BlogPosting 的描述優先來源       |
| 有效 Meta Description | HTML description meta、Open Graph 與 Twitter 描述；也供空摘要回退 |

一般文章先填標題與摘要即可。文章頁型為「使用文章摘要」且單筆未覆寫時，Meta Description 跟著摘要更新；已明確填入的 Meta Description 不會被摘要或全域設定蓋掉。

例如摘要寫「整理改版前的內容盤點與上線準備」，Meta Description 另寫搜尋文案，列表仍優先顯示摘要。摘要空白時，列表等位置才使用該篇有效 Meta Description；RSS 頻道描述仍由全站 RSS 設定管理。

摘要最多 300 字元；單筆 Meta Description 明確覆寫時為 1–300 字元，留白可繼承。字數是資料限制，不是搜尋結果必然展示的長度。

## 查看生效來源與恢復繼承

設定表單的「目前生效結果」依當前表單與 Core 相同的逐欄規則，顯示標題、描述、索引、分享圖及來源；來源區分單筆、頁型、全域、使用內容、不使用圖片與適用的強制規則。這是設定解析提示，不代表每個公開頁面都已完成驗收。

全站頁型以示例文章／分類／Tag 描述計算，沒有實際文章精選圖；分類與 Tag 表單明示尚未計入文章數。文章設定顯示預定的 SEO 設定，安全預覽另有強制 noindex。空分類／Tag、404 與安全預覽的最終規則，仍須依對應頁面模型及實際輸出確認；先分清楚設定來源，再判斷要改哪一層。

以下使用示範網站「山嶼設計工作室」，不會自動修改現有資料：

1. 在示範站的全域設定標題模板 `{title} | {siteName}`；文章頁型的標題模板選繼承、描述選使用文章摘要、圖片選使用文章精選圖片，保存。
2. 選一篇已發布的示範文章，標題設為「網站改版準備」，填摘要與精選圖，單筆 SEO 欄位先維持繼承。
3. 查看生效結果：標題為「網站改版準備 | 山嶼設計工作室」，描述與圖片依文章頁型採摘要及精選圖。
4. 只填單筆 SEO Title「網站改版規劃與準備」，保存。標題改用該完整文案，來源為單筆；描述、索引及圖片仍依原策略繼承。
5. 清空單筆 SEO Title，恢復繼承並保存。生效結果重新套用上層模板；不把先前計算出的完整標題貼回欄位。
6. 檢查來源預覽，完成正式 Build 後，再用成功網站確認 title、分享資料與頁面內容。

頁型的「清除此類型自訂內容」會將該類型各欄位改為繼承全域，不是恢復文章初始的摘要／精選圖策略，也不改文章、分類或 Tag 的單筆覆寫。只想恢復某一欄時，使用該欄的繼承選項。

## 系統管理的技術輸出

| 項目         | 系統行為與作者要確認的資料                                                                                              |
| ------------ | ----------------------------------------------------------------------------------------------------------------------- |
| Canonical    | 由正式 `siteUrl` 與 Core 路由建立；作者先確認網域、分類與 slug；404 不輸出 canonical                                    |
| Meta Robots  | 由有效索引設定輸出 `index,follow` 或 `noindex,follow`                                                                   |
| `robots.txt` | 提供 `Allow: /` 與 Sitemap 網址；頁面索引策略由 Meta Robots 表達                                                        |
| Sitemap      | 只納入可索引的公開路由，與同一份 Core 模型保持一致                                                                      |
| OG／Twitter  | 共用有效標題、描述及同一張解析後的分享圖；無圖省略圖片標籤，Twitter Card 使用 `summary`，有圖使用 `summary_large_image` |
| JSON-LD      | 文章有正式網址與日期時建立 BlogPosting；適用的麵包屑建立 BreadcrumbList                                                 |

BlogPosting 的 `headline` 使用文章標題，不是 SEO Title；`description` 優先使用摘要，再回退有效 Meta Description。作者、日期與網址也來自實際資料，固定頁不冒用 BlogPosting。一般編輯不需手工加入另一份 canonical、robots 或 JSON-LD。

已發布文章選「不允許索引」仍輸出公開 HTML、列表、搜尋與 RSS，只從 Sitemap 排除；草稿才完全排除這些公開集合。單一分類／Tag 的公開文章集合為空時，仍輸出一頁並強制 noindex；404 與 Studio 安全預覽也固定 noindex。文章總覽、分類總覽、Tag 總覽或零筆搜尋結果，不因空集合就自動套用這條規則。

分類／Tag 靜態分頁各有自己的 canonical；搜尋的查詢與分頁參數共用 `/articles/` 的 canonical。更改分類或 slug 後，舊網址轉址另行規劃。

## 內容、連結與分享圖品質

- 標題與摘要清楚交代頁面內容，不用相同空泛文案填滿所有欄位；技術敘述、來源與日期由作者查核。
- 文章 H1 由版型輸出，正文使用 H2–H6 並提供合法唯一 id；Core 目前把 H2／H3 納入目錄。
- 站內連結指向真正相關的頁面與錨點；分類表達主要架構，Tag 幫助橫向探索，不以大量重複標籤代替內容。
- Alt 描述圖片傳達的資訊，裝飾圖片可明確留空；關鍵文字與操作步驟也應保留在正文。
- 分享圖使用媒體庫的受管變體，常用 1200 × 630；檢查裁切或留白後主體與文字是否完整，與正文響應式圖分開選用。

設定頁型分享圖或單筆指定圖片時，先選媒體，再選實際尺寸、按「使用這個尺寸」，最後保存所在表單。OG 與 Twitter 共用這張分享圖，目前沒有獨立 Twitter 圖片覆寫欄位。分享圖與文章精選圖可以不同；單筆「不使用圖片」不會刪掉文章封面。

## 保存與確認結果

1. 在 Studio 查看生效值與來源，保存文章或設定；IDE 編輯也保留原本的繼承狀態。
2. 已發布文章與有效公開頁面在 `4321` 檢查已保存來源；草稿在 Studio 重讀與安全預覽確認。安全 iframe 不執行完整網站互動。
3. 依[新增文章流程](新增文章流程.md)執行內容驗證與正式 `pnpm build`，或使用 Studio「更新網站」。
4. 成功後在 `4322` 檢查實際標題、摘要、分享資料與連結；需看 Head 時使用瀏覽器開發工具或頁面原始碼。

正式 Build 會核對 HTML SEO、canonical、robots、Sitemap、RSS、搜尋與媒體的一致性。保存與本機建置不等於公開部署；搜尋引擎及分享平台的展示、收錄與快取仍有各自的處理時間。

交付時回報調整了哪一層、哪些欄位，以及實際確認的版本與結果。內容價值、搜尋收錄與排名不能只用欄位合法或工具高分代替。
