# 版本更新與備份

這個系統允許直接修改原始碼，因此你的網站包含兩部分：**自己的程式修改**及**文章、設定與媒體等作者資料**。更新系統時要同時保留兩者，不能把新版壓縮檔整包蓋在目前專案上。

## 0. 版本相容性

### 由 0.3.1 升級至 1.0.0

1.0.0 沿用 0.3.1 的程式行為與資料格式，無須另做資料轉換。保留自己的文章、媒體、自訂頁面、版型及 Cloudflare 設定，依下方流程先備份，再在副本完成驗證。若自己的 `.env` 已設定 `RELEASE_VERSION`，將它更新為 `1.0.0`，其餘個人設定保留。

### 早期版本：升級到 Foliohaven 0.3.0

0.3.0 可讀取原 0.2.0 的文章、設定及媒體資料；未填的新欄位套用預設值，原有單筆 SEO、文章網址及媒體 URL 保留。套件名稱改為 `@foliohaven/*`，自訂程式中的舊 imports 與 `pnpm --filter` 必須一起更新；Docker 內部工作路徑與 image 名稱也改用新名稱，請比較自己的 Compose 覆寫設定。

保存文章或設定後，新版可能寫出摘要、延伸閱讀、頁型 SEO、分享圖來源及圖示欄位。舊版的嚴格 Schema 不接受這些新欄位，因此降版必須還原升級前完整備份及原程式版本；只 checkout 舊程式不足以還原。`.alfred/` 工作、復原及部署紀錄與既有 Cloudflare 資源識別仍保留相容性，不需要為產品改名重新命名或清空它們。

## 1. 停止後備份完整專案

1. 保存 Studio／IDE 尚未保存的內容，等媒體處理、網站更新與 Cloudflare 發布／還原工作結束；結果未知時先保留紀錄並查詢狀態。
2. Docker 執行 `docker compose down`；原生環境以 Ctrl-C 停止自己的作者服務及預覽。確認沒有另一個 IDE／AI 同時修改。
3. 將完整專案複製到專案以外的私有位置並保留權限，記下根 `package.json` 的版本。備份不加入 Git、image 或公開網站。

完整備份至少涵蓋下列資料；保存整份專案可降低遺漏自訂檔案的風險。

| 項目                                                                  | 保存原因                                                                     |
| --------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| `content/`                                                            | 自己的文章、網站設定、分類、Tag 與固定頁 JSON                                |
| `media/source/`                                                       | 原始圖片、影片與媒體設定                                                     |
| 自訂程式及資源                                                        | 首頁、固定頁、文章版型、Header／Footer、CSS、Astro 入口、registry 及其他修改 |
| `.alfred/`、`dist/`                                                   | 交易、工作與復原證據，以及對應的成功網站                                     |
| `package.json`、workspace manifests、lockfile、工具與容器設定         | 還原同一版本及相依套件所需資料                                               |
| 自己的 `.env`、`cloudflare.config.json`、`.env.cloudflare` 等本機設定 | 連接埠、UID／GID、Cloudflare 部署目標與憑證；含私密值時更應妥善保護          |

Git 可保存自己的原始碼修改，但不取代作者資料與 `.alfred/` 的完整備份。只有 `dist/` 也不足以恢復可編輯的網站；Studio 內的版本及垃圾桶同樣不能代替外部備份。

使用 Cloudflare 時，`.alfred/deployments/<UUID>/` 包含固定網站副本、上傳紀錄與 `backups/r2/` 覆寫前備份；缺少它可能無法還原舊媒體。根 `cloudflare.config.json` 與 `.env.cloudflare` 也需帶入私有備份，保留 0600 與帳號擁有權。R2 中的物件與 CDN 快取不屬於本機備份，不會因換回舊專案就自動回復。

## 2. 在另一份目錄準備新版

1. 閱讀新版 [CHANGELOG](../../CHANGELOG.md) 及使用要求，確認版本、工具鏈、資料格式與必要轉換。若新版本宣告不相容且沒有可用轉換方式，先保留舊版，不直接嘗試覆蓋。
2. 把新版放到另一個目錄，保留舊專案與備份。將自己相對於舊版的程式修改，逐項比較並套用到新版；特別檢查共用元件、樣式、固定頁入口、registry 及自訂 Schema。
3. 在兩邊服務都停止的狀態下，帶入同一份備份的 `content/`、`media/source/`、`.alfred/`、`dist/` 及需要的私有設定；取代新版隨附範例，不把兩套文章及交易資料混在一起。保留自己的 `content/site.json`，尤其正式網站網址 `siteUrl`，不要以新版中性範例覆蓋。若版本需要轉換，依該版指示操作並保留轉換前備份。
4. 檢查 `.env` 與新版 `.env.example` 的差異，保留自己的值並補齊新增設定。新版套件與 lockfile 以新版為準；不要把舊 lockfile 蓋回去來繞過相依問題。自訂依賴需重新核對相容性。
5. 使用 Cloudflare 時，另比較 `cloudflare.config.example.json`、`.env.cloudflare.example` 與[部署文件](../deployment/Cloudflare部署.md)，保留自己的目標與憑證；不要以範例覆蓋實際檔案。新舊副本不要同時對同一 bucket 發布，本機鎖不能協調不同副本或不同主機。

可讓 AI 協助比較新舊程式，但先要求它閱讀 AGENTS.md，列明哪些是自己的修改，並保護作者資料。不要讓工具只根據同名檔案決定覆蓋。

## 3. 啟動並檢查新版副本

Docker 依新版 README 重新建立對應 image；`.env` 如有 `RELEASE_VERSION`，需與新版根 `package.json` 一致。原生環境切換到新版要求的 Node.js／pnpm，再做 frozen 安裝及環境檢查。

舊工作階段已停止後，才能啟動新版副本。即使使用不同連接埠，也不要讓兩套服務同時操作同一份作者目錄。`.alfred/` 與 `dist/` 保持在專案所在檔案系統中，不各自掛成獨立 mountpoint。

```bash
pnpm run setup
pnpm typecheck
pnpm validate:content
pnpm verify
```

原生環境先停止新版副本的作者服務，再執行上述檢查；整合及完整驗證會使用 4321／5173／3001。Docker 的完整驗證改用一次性容器，不在活動中的 app 內執行：

```bash
docker compose stop app repair
docker compose run --rm --no-deps app pnpm verify
```

驗證成功後再 `docker compose up -d --wait --wait-timeout 600 app`。完整 `verify` 包含工具檢查、型別、內容建置及測試；任何必要檢查失敗，先查明原因，不刪除測試或私有紀錄來換取通過。

再人工檢查 Studio 可讀取自己的文章與設定、`4321` 的自訂頁面與版型，以及 `4322` 成功產物的文章、導覽、圖片、影片與 SEO。確認後才採用新版專案並重新交付完整 `dist/`。建置成功不會自動部署公開網站。

Cloudflare 使用者再執行 `pnpm deploy:cloudflare --dry-run` 檢查新版部署入口；真正發布與正式網址驗證依[Cloudflare 部署](../deployment/Cloudflare部署.md)操作。既有網域規則通常可沿用，仍需核對發布前後與可變媒體的公開結果。

## 4. 失敗時保留現況並復原

- 新版相容或程式檢查失敗：停止新版，保留失敗副本與診斷，使用未修改的舊專案及對應環境繼續工作。不要把新版修改過的資料直接混回舊版。
- 來源或產物處於待復原狀態：依 README 啟動修復模式，在 Studio「衝突與復原」比較版本並明確選擇；不手工清空 `.alfred/` 或覆蓋 `dist/`。
- 需要外部備份還原：先停止服務並另外保存目前專案，再還原**同一份完整備份**及其對應程式版本、工具鏈與權限；不要拼接不同時間的文章、媒體、交易資料及產物。
- Cloudflare 發布失敗或結果未知：先用該次 `deploymentId` 查詢，不把本機回到舊版當成雲端也已回復。明確還原需有對應紀錄、R2 備份與仍可回復的 Worker 舊版本；完成後另驗證公開網址與 CDN。不要刪除部署紀錄來略過衝突。

平時只改文章、頁面或 CSS，不需每次重做容器。更動依賴、工具鏈或容器設定後，才依對應版本重建；公開網站仍以重新建置的完整 `dist/` 更新。
