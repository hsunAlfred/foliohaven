# 網站開發與品質標準

本文件是 Foliohaven 網站開發、客製及內容維護時，人與 AI Agent 共用的品質基準。先讀 [AGENTS.md](../../AGENTS.md) 與 [README](../../README.md)，再依任務讀固定頁、版型、文章或部署文件；共通要求以本文為準，任務文件補充操作與專屬契約。

目標是讓可修改原始碼的網站持續保持完整內容、友善 SEO 與良好閱讀體驗，並以手機、桌機接近滿分的 PageSpeed 結果作為開發目標。PageSpeed 由手動量測驗收，`pnpm verify` 不自動評分；分數是開發與人工驗收目標，不代表隨附範例版型或客製網站已經量測達標。

## 架構與內容

- 主要內容、導覽、文章、列表、TOC 與 SEO 在建置時輸出完整 HTML；停用 JavaScript 仍可閱讀與循連結瀏覽。
- 沿用 Core 的模型、路由、分類、分頁、TOC、SEO 與搜尋規則，React／Astro 只接收並呈現模型，不另算同一套規則。
- 固定頁完成 React 主體、公開 export、Astro Entry 與 registry；文章沿用 HTML／JSON 與共用版型，不逐篇建立元件。
- 使用套件公開 exports；共用樣式改來源，不跨套件讀 `src/`，也不直接修正 `dist/`。
- JavaScript 只增強需要互動的部分，保留既有搜尋 island 契約，不為一般展示任意加入 hydration、重型套件或第三方腳本。
- 保留作者內容、自訂版型與無關修改；程式與設定變動依授權範圍進行，來源保存、本機 Build 與外部發布分開。

## 圖片、影音與載入

- 媒體使用已處理的受管路徑與實際輸出；固定頁及共用 UI 的引用納入 `mediaRefs`，原始素材與預覽 API 不進公開內容。
- 圖片提供正確比例的 `width`／`height`；特定構圖框可用 `aspect-ratio` 預留空間並明定 `object-fit`，避免拉伸圖片。
- `srcset` 只組合同一構圖的有效尺寸；`sizes` 配合實際欄寬與斷點，不將分享裁切圖混入正文候選。既有模型與 Core 提供的 `sizes` 是通用預設，不會分析版型 CSS；客製時需核對實際呈現寬度。
- 首屏且可能成為 LCP 的圖片使用 `loading="eager"`，主要候選加 `fetchpriority="high"`；離屏圖片使用 `loading="lazy"`，不要將所有圖片都設為高優先序。
- 圖片使用 `decoding="async"`。`ManagedImage` 預設為 lazy／async，`priority` 設為 `true` 時使用 eager／high 並保留 async。Core 可補正文媒體缺少的尺寸等可推導屬性，不會自動加入 `loading`、`decoding` 或 `fetchpriority`，需依位置明確設定。
- 影片、Poster 與自行加入的 iframe 同樣預留尺寸或比例；影片可操作、可捲動，嵌入資源的載入與播放不應阻擋主要內容。iframe 的尺寸與載入由頁面或正文設定，不屬於媒體庫自動處理。

## 字型、布局與閱讀互動

- 優先沿用既有系統字型；使用 Web Font 時控制字型檔與字重，設定適合的 `font-display` 與接近的 fallback，檢查替換前後換行及區塊高度。
- 圖片、工具列、目錄、搜尋等待區及延遲區塊在初始 HTML／CSS 預留合理空間，JS 增強前後維持幾何，避免後插入內容推動已讀位置。
- 程式碼與寬表格在區塊內捲動；垂直到邊界後仍能接續頁面捲動，不用整頁橫向溢出解決內容寬度。
- 保留閱讀位置、同頁錨點、返回／前進及 modal 的捲動協作；使用者開始操作後，不持續用程式修正其位置。
- 手機檢查工具列收合、旋轉、觸控捲動與長內容；中性及自訂版型的 DOM 接線依[跨平台閱讀與版型整合 Memo](跨平台閱讀與版型整合Memo.md)核對。

## 語意、可及性與響應式

- 使用適當的 `main`、`nav`、`article` 與表單語意；頁面主標題與各級 heading 表達結構，避免為字級效果跳用標題。
- 資訊圖片有能傳達用途的 Alt；裝飾圖片明確使用空 Alt，重要資訊不能只存在圖片或顏色中。
- 控制項有可理解名稱、鍵盤操作、可見 focus 與合理焦點順序；dialog 開關處理焦點與背景捲動，狀態提示可被輔助技術理解。
- 文字、連結、控制項及 focus 維持足夠對比；不以關閉檢查或隱藏資訊換取分數。
- 小螢幕、長標題及長連結不撐破布局；文字放大至 200% 仍可讀與操作，保留使用者頁面縮放，尊重減少動態效果設定。
- 自動可及性分數與人工鍵盤、閱讀及縮放檢查共同構成交付證據。

## SEO 與內容入口

- 依[SEO 設定與繼承](SEO設定與繼承.md)管理全域、頁型與單筆設定，優先保留繼承，只在有實際需要時覆寫。
- 檢查有效 title、description、canonical、索引與分享圖來源，保留適用的結構化資料、RSS、Sitemap 及正常 HTML 導覽。
- SEO 與內容使用同一份正式 URL、文章及分類資料；草稿隔離、noindex、搜尋 query 與靜態分頁沿用 Core 契約。
- 自訂固定頁完成自己的 registry SEO；搜尋結果互動不是額外的靜態 SEO 落地頁，404／預覽維持既有索引規則。

## PageSpeed 目標與指標

手機與桌機分開量測，代表頁均以以下 Lighthouse 類別分數為開發目標：

| 類別           | 目標分數 |
| -------------- | -------- |
| Performance    | ≥95      |
| Accessibility  | 100      |
| Best Practices | 100      |
| SEO            | 100      |

SEO 100 適用於應索引的正常公開頁；404、預覽、空分類／Tag 等依預期 noindex 驗收，不為分數改變索引策略。

下列良好體驗門檻用來判讀瓶頸，不等同於達到 Performance 95；[Lighthouse 依多項指標加權計分](https://developer.chrome.com/docs/lighthouse/performance/performance-scoring)。

| 指標                                | 參考值與資料性質                                       |
| ----------------------------------- | ------------------------------------------------------ |
| [FCP](https://web.dev/articles/fcp) | ≤1.8 秒；lab 可供診斷，field 以手機／桌機各自 p75 判讀 |
| LCP                                 | ≤2.5 秒；區分本次 lab 與實際使用者 field               |
| CLS                                 | ≤0.1；同時觀察載入及閱讀互動的布局變動                 |
| INP                                 | ≤200 毫秒；field p75，不能用一次載入或 lab TBT 代替    |

[Core Web Vitals](https://web.dev/articles/vitals) 以手機／桌機分組的 field p75 判讀；[PSI 的 CrUX](https://developers.google.com/speed/docs/insights/v5/about) 通常是最近 28 天資料，需記錄是頁面或 origin 範圍。缺少足夠資料時標記「尚無 field 資料」，不推論已通過。

## 代表頁與手動量測

| 代表頁         | 選樣重點                                  |
| -------------- | ----------------------------------------- |
| 首頁           | 品牌、導覽、精選及首屏圖片                |
| 自訂固定頁     | About、FAQ 等實際新增頁面與專用媒體／互動 |
| 長文章         | 圖片、程式碼、表格、TOC 與延伸閱讀        |
| 分類／Tag 列表 | 長標題、縮圖、靜態分頁與導覽              |
| 文章總覽／搜尋 | 初始列表、hydration 與查詢／返回操作      |

1. 先確認是本次來源成功 `pnpm build` 的產物，在 `4322` 檢查上述頁面、裝置寬度與閱讀操作；`4321` 只協助開發。
2. 本機性能初驗使用瀏覽器既有 Lighthouse，固定 Chrome／Lighthouse 版本、手機／桌機 preset、網路與 CPU 節流、冷啟動及快取條件，避免其他重負載影響比較。
3. 公開部署取得明確授權、正式網域設定完成後，再以正式 HTTPS URL 做 PSI 確認，涵蓋 CDN、實際媒體與第三方資源；不拿本機時間直接比較遠端時間。
4. 每個受測 URL、裝置 preset 與條件組合各做 3 次；保留各次類別分數、指標與報告，各類別分數及指標分別取中位數摘要，不挑最高分當結論。
5. PSI 使用報告當時的環境；記錄報告中的版本、裝置、網路／CPU條件及可觀察的快取狀態。版本或條件不同就分批記錄，無法控制的條件明示。
6. 每批記錄日期、受測來源版本、Build／部署識別、URL、工具版本、裝置與條件、各次數值、中位數、問題與未驗範圍；報告放私有驗收位置，不公開憑證或個人資料。
7. 搜尋、目錄及返回操作另記人工觀察；有 field 資料時另列 p75、時間窗及頁面／origin 範圍，不與 3 次 lab 中位數合併。

## 依修改範圍選擇檢查

| 修改範圍                             | 檢查範圍                                                                    |
| ------------------------------------ | --------------------------------------------------------------------------- |
| 純文字、日期、摘要或既有 SEO 值      | 沿用內容驗證、需要的 Build 與受影響頁面檢查，不因每篇文字變更重跑全站 PSI   |
| 新文章或替換媒體                     | 加查尺寸、Alt、連結與載入位置；若新增大圖、嵌入或改變首屏，量測受影響代表頁 |
| 新固定頁、共用樣式、字型、版型或互動 | 檢查受影響頁型與手機／桌機；共用變更涵蓋代表頁並依上述方式量測              |
| 部署分流、快取或第三方資源           | 在已授權發布後，核對正式網址與受影響代表頁的 PSI 結果                       |

依任務沿用現有 `pnpm typecheck`、相關測試、`pnpm validate:content`、正式 `pnpm build` 與需要的 `pnpm verify`；實際執行條件及停止作者服務的規則見 README／AGENTS。這些檢查驗證程式與產物契約，額外的 Lighthouse／PSI 手動量測驗證本次頁面表現。

## 交付紀錄

- 說明改了什麼、影響頁型、來源／Build 版本，以及實際執行的檢查與結果。
- 有量測就附條件、3 次結果、中位數與報告；未量測、沒有 field 資料或未使用實機的範圍逐項標明。
- 未達目標時列出頁面、失敗項目與影響，保留問題及處理結果；測試全過或單一案例高分不代替本次品質結論。
- 公開發布依使用者授權；本機交付可先完成 `4322` 與 lab 初驗，正式 PSI 結果在網域可用後補齊。
