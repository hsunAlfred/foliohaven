# 新增文章流程（Article Creation Workflow）

本流程對應目前的 HTML／JSON、Studio、Core、媒體與完整建置介面。最終交付是根目錄 `dist/`；保存來源、發布狀態與成功 Build 是三個不同動作。

新增文章只需建立 `content.html` 與 `meta.json`。所有文章共用 `@foliohaven/ui` 的 `ArticlePage`、Core 規則、共用 CSS 與 `site/src/pages/[...article].astro`，不逐篇新增 React／Astro 元件。

## 1. 操作入口與前置條件

先依[README](../../README.md)完成原生環境或 Docker 的配置；若尚未決定首頁、固定頁及文章版型，先讀[版型與樣式調整](版型與樣式調整.md)。Docker 在專案根目錄啟動，主機不需要 Node.js、pnpm 或特定編輯器：

```bash
docker compose up -d --build --wait --wait-timeout 600
```

開啟 `http://localhost:5173/`。`4321` 是目前保存內容的開發預覽，`4322` 是最近成功更新的網站；API `3001` 僅供本機 Studio proxy 使用，不對外公開。首次沒有網站時啟動程序會建立範例產物，已有網站時不自動發布尚未更新的內容。權限、SSH 轉送與修復模式見[README](../../README.md)。

原生環境依 README 準備完成後，以 `pnpm start` 啟動相同三個網址。本文檢查／建置指令使用 `docker compose exec app`；在原生環境或已進入容器的終端，省略此前綴。也可使用 `pnpm dev`，需要成功產物預覽時另開終端執行 `pnpm preview`；選用 Dev Container 時透過編輯器的連接埠轉送開啟網址。同一工作區一次使用一種啟動方式。

Studio 使用淺色介面，桌面左側導覽包含「文章」、「分類與 Tag」、「全站設定」、「媒體庫」、「網站更新與工作」、「衝突與復原」。窄螢幕從「開啟導覽」展開功能選單；頂部顯示工作區狀態及 Studio／IDE 模式，可在「工作區」選單切換模式。此介面管理文章與系統設定；固定頁的 React／Astro 及專用 JSON 仍使用 IDE 維護。

| 編輯方式   | 使用方式                                                                                                             |
| ---------- | -------------------------------------------------------------------------------------------------------------------- |
| Studio     | 使用預設 Studio 模式，透過介面保存及發布；不要同時用 IDE 保存同一批來源                                              |
| IDE        | 先按「切換 IDE 模式」，再直接編輯檔案；Studio 來源寫入暫停，讀取及預覽仍可用。編輯完先檢查，再切回 Studio 並重新載入 |
| 只開發網站 | 可用 `pnpm dev:site`；若仍要透過介面切換模式或管理內容，使用完整 `pnpm dev`                                          |

IDE 模式不會封鎖 IDE 的檔案權限，也不禁止 CLI `pnpm build`。兩種工具同時保存仍可能產生衝突；不要把模式當成能攔下所有外部編輯的鎖。

目前範例有「筆記」`notes`、「工具」`tools` 兩個同層分類，及 `example`、`workflow`、`media` 三個 Tag。新分類／Tag 先在「分類與 Tag」建立；不會從正文自動推測。

在分類／Tag 頁籤按「新增分類」或「新增 Tag」，或點既有名稱，開啟單筆編輯彈窗；描述可用多行輸入。按「保存分類／保存 Tag」即保存該次完整設定變更，成功後關閉彈窗，不需第二次整頁保存。移除項目也會直接檢查引用並保存，仍被文章或導覽使用時明確拒絕。

改顯示名稱時，只要編輯「分類名稱／Tag 名稱」。要改連結本身，則從既有項目的「修改網址」，或清單下方「修改分類或 Tag 網址」進入：

1. 在「項目類型」選分類或 Tag，再從「要變更的項目」選名稱。
2. 填「新的網址名稱」，例如將 `notes` 改成 `journal`，不要貼整個網址。
3. 對照畫面的「目前網址／變更後網址」，按「查看變更影響」。
4. 確認受影響文章、子分類及導覽後，再按「確認變更網址」。完成後更新網站。

網址變更會更新相關設定，但不會自動轉址，也不會重寫正文中的舊連結；請依診斷逐篇修正。改名稱不等於改網址，不需要為了名稱變更使用這個流程。

## 2. Step 1：建立草稿與文章識別

Studio：進入「文章」→「新增文章」，填寫內容後按「建立草稿」。第一次保存只建立 draft；保存成功取得 articleId 後，才可使用「發布目前內容」。

桌面編輯區包含 HTML 正文、即時預覽及文章設定。視窗寬度在1280px（含）以下會提早切換為「正文／預覽／文章設定」三個頁籤，讓編輯器與預覽各有足夠空間；切換本身不保存也不捨棄內容。標題、摘要及 Alt 使用多行輸入，Slug 等短欄位保持適當寬度。工作室採自託管 Noto Sans TC 字型與16px基本文字，不需要另外安裝字型。

IDE：在 `content/articles/` 下建立單層目錄，例如：

```text
content/articles/my-first-note/
├── content.html
└── meta.json
```

`my-first-note` 是本機文章識別，不是公開 URL。articleId 為 1–80 字元小寫英數與連字號；Studio 自動使用 `article-<UUID>`。不要在 meta.json 另加 `id`，也不要任意改既有目錄 ID。

最小但完整的草稿 `meta.json`：

```json
{
  "status": "draft",
  "title": "",
  "slug": "",
  "category": null,
  "tags": [],
  "publishedAt": null,
  "updatedAt": null,
  "featuredImage": null,
  "featuredImageAlt": "",
  "seo": {
    "title": null,
    "description": null,
    "index": null,
    "ogImage": null
  }
}
```

草稿允許未完成的標題、slug、分類、正文及語意關聯；錯誤型別、未知欄位、超長與無效日期仍會拒絕。`null` 是未設定，不要改成日期空字串或圖片空字串。

## 3. Step 2：撰寫 HTML 正文及 TOC

將下列內容放入 `content.html`，或貼入 Studio HTML 編輯器：

```html
<p>這是第一篇筆記，示範共用文章樣式與靜態目錄。</p>

<h2 id="preparation">準備內容</h2>
<p>正文使用 HTML，文章屬性另存 JSON。</p>

<h3 id="files">必要檔案</h3>
<ul>
  <li><code>content.html</code>：正文。</li>
  <li><code>meta.json</code>：文章屬性。</li>
</ul>

<h2 id="verification">驗證結果</h2>
<p>
  <a href="#preparation">回到準備內容</a>，或前往<a href="/category/notes/"
    >筆記分類</a
  >。
</p>
```

- 保存 UTF-8／LF；正文不自動格式化，CRLF、CR 與 NUL 明確拒絕。
- 不含 `<html>`、`<head>`、`<body>` 或 H1。文章主標題由共用 ArticlePage 輸出。
- 每個 H2–H6 都有非空、唯一、無空白的 `id`，不要占用 `ui-` 前綴；Core 以 H2／H3 建立 TOC。
- 站內連結使用根路徑（例如 `/notes/article-basics/`）或 `#fragment`；Build 檢查路由及錨點是否存在。不要引用本機原始檔案路徑。
- 表格、清單、程式碼及媒體都沿用共用文章樣式。修改所有文章的版型，入口是 `packages/ui/src/article/ArticlePage.tsx` 及 `packages/ui/src/styles/index.css`。

TOC 與正文都已存在於正式初始 HTML，不需要瀏覽器 JavaScript 載入後才顯示。作者 HTML 為可信任本機內容；Studio 預覽以 sandbox／CSP 隔離原文 script，不會因此改寫保存原文。

## 4. Step 3：完成 Metadata 與 SEO

將草稿補成下列完整的可發布資料；這個範例使用已存在的 `notes`／`example`，暫無圖片：

```json
{
  "status": "draft",
  "title": "我的第一篇筆記",
  "slug": "my-first-note",
  "category": "notes",
  "tags": ["example"],
  "publishedAt": "2026-10-23T09:00:00+08:00",
  "updatedAt": "2026-10-23T09:00:00+08:00",
  "featuredImage": null,
  "featuredImageAlt": "",
  "seo": {
    "title": null,
    "description": "示範以 HTML 與 JSON 建立文章，完成預覽、發布與靜態建置。",
    "index": null,
    "ogImage": null
  }
}
```

發布時保留上述內容，只把 `status` 改為 `published`，或在 Studio 按「發布目前內容」。若同一分類已有相同 slug，請先另取唯一 slug。

| 欄位                   | 正式規則                                                            |
| ---------------------- | ------------------------------------------------------------------- |
| title                  | 發布時 trim 後 1–200 字元；頁面 H1 使用此值                         |
| slug                   | 1–80 字元 lowercase kebab-case，不得純數字；與分類組成公開 URL      |
| category               | 既有完整分類 path，例如 `notes`；一篇只有一個分類                   |
| tags                   | 既有 Tag slug 陣列，最多 20、不重複；`[]` 合法                      |
| publishedAt／updatedAt | 含 `Z` 或明確 offset 的有效日期，最多毫秒三位小數；更新不得早於發布 |
| featuredImage          | `null` 或媒體庫提供的 `/media/<UUID>/image.webp` 等受管圖片路徑     |
| featuredImageAlt       | 最多 300 字元；有精選圖時必須明確提供，裝飾圖可用 `""`              |
| seo.title              | `null` 將文章標題套用頁型／全站標題模板；覆寫值為 1–200 字元，直接作為 SEO 標題 |
| seo.description        | `null` 繼承頁型／全域；覆寫時填 1–300 字元                                         |
| seo.index              | `null` 繼承頁型／全域設定；`true`／`false` 明確覆寫                       |
| seo.ogImage            | 受管圖片路徑或 `null`，配合 `seo.imageSource` 決定繼承、指定或不使用            |

正文上限 5 MiB、meta.json 上限 64 KiB（皆計 UTF-8 bytes），文章數上限 10,000。

來源日期保留作者傳入的時區字串；Core 比較同一 UTC instant，API 回應日期為 UTC `Z`，畫面依 `site.timeZone` 顯示。GET、保存及 Build 不自動把日期改成現在；Studio 的「填入目前時間」是作者明確觸發的動作。從 API 重新載入後再保存可能使用等價的 UTC 字串，不代表發布時間改變。

Studio 操作「發布與更新時間」：

1. 在文章設定展開「發布與更新時間」，直接輸入例如 `2026-10-24 14:30`；可加入秒數與毫秒，也接受貼上原本帶時區的 ISO。人工輸入依全站設定的「顯示時區」解讀，與瀏覽器所在時區無關。
2. 或按欄位旁的日曆按鈕，在自製月曆選年、月、日，再選小時、分鐘、秒。年月切換會保留可用的日期；「現在」將彈窗的選擇改成目前時間。日期與時間、網站時區及 UTC 時差會一起顯示。
3. 按「套用時間」才把彈窗選擇帶回文章編輯器；「清除」會明確將該欄設為未設定並關窗。這兩種操作仍要保存文章才會寫入檔案。取消、Escape 或返回只關閉彈窗，有尚未套用變更時先確認捨棄。
4. 日期不完整、無效或時區調整造成不存在時刻時，保留輸入並提示原因，保存暫停；可修正、從日曆重新選擇或清空。遇到同一時間出現兩次，會顯示兩組時差，明確選擇要使用的時段。既有有效日期不因開關日曆而被改寫；原有毫秒保留。

單行日期欄、日曆按鈕、年月與時間選單沿用42px高度；手機彈窗可捲動。日曆支援方向鍵、Home／End、PageUp／PageDown及Enter／Space選日，彈窗內Ctrl／Cmd+S不會穿透保存文章。草稿可留空，發布時兩個時間皆須有效，更新不得早於發布；未來日期仍不代表自動排程發布。

此範例公開 URL 為 `/notes/my-first-note/`，輸出 `dist/notes/my-first-note/index.html`，與目錄 ID 是否同名無關。

`seo.index=false` 不是草稿：仍產生文章 HTML，仍列入公開列表、RSS 與搜尋，只排除 Sitemap，並輸出 `noindex,follow`。草稿則不進入任何上述公開集合。未來日期不會自動排程發布，`status` 才是發布開關。

Studio 的 SEO 欄位標題保留英文，補充說明與選項使用中文：

| 介面名稱         | 對應設定與操作                                                                                                                                 |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| SEO Title        | `seo.title`；空白時將文章標題套用頁型／全站模板；填入時直接使用該標題                                                                                                        |
| Meta Description | `seo.description`；多行搜尋描述；留白繼承頁型／全域，不強制每篇自填                                                                                                    |
| OG Image         | `seo.imageSource` 選繼承、指定圖片或不使用；指定時由選圖彈窗先選媒體，再選尺寸。頁型設定可優先採文章精選圖 |
| Indexing         | `seo.index`；「使用全站預設值」繼承、「允許索引」可被搜尋引擎收錄、「不允許索引」不索引但內容仍公開                                            |

網站預設位於「全站設定」的「SEO 與社群分享」，使用 `SEO Title Template`、`Default Meta Description`、`Default Indexing` 及 `Default Social Image`。此處的圖片也使用相同選圖彈窗；選 `不設定全站預設圖片` 保存 `null`，不額外建立預設分享圖。

欄位選擇使用預設值或留白時，介面會直接顯示目前實際採用的標題、描述、索引設定，以及分享圖縮圖、名稱與繼承來源；不需要猜測「預設」指哪個值。標題包含當前全站模板的結果。這些是依目前編輯內容計算的提示，不會把繼承改存為固定覆寫；發布前確認有效描述是否適合本篇，可保留繼承或單筆覆寫。全站設定分為五個區塊，桌機用頁籤、手機用「設定區塊」選單切換，一次只顯示一區，標題放在卡片內。切換保留修改，完成後用「保存全站設定」一併保存；點錯誤摘要可顯示並聚焦其他區塊的問題欄位，保存前的格式檢查未通過時也會自動定位。

### 摘要、延伸閱讀與頁型設定

`excerpt` 是獨立文章摘要，最多 300 字元；首頁、列表、搜尋、RSS 與文章導言優先使用它，再依 Core 的有效描述回退。它不會自動覆蓋單筆 Meta Description。

`relatedReading` 保存 `{title, articleIds}`，最多 20 篇，依選取順序顯示。請選其他已發布文章，不可重複、自我引用或指向不存在／草稿文章；空清單不輸出區塊。Studio 可搜尋、分頁選取並排序，刪除被其他文章引用的文章會回應衝突，需先移除引用。

全站設定的 SEO 頁型包含首頁、文章、文章總覽／搜尋、分類總覽、分類頁、Tag 總覽、Tag 頁及 404。每欄獨立依「單筆覆寫 → 頁型 → 全域」判斷；Indexing 的 false 與分享圖的 none 都是明確設定。空分類／Tag、404 與預覽另有固定索引規則，介面會區分繼承設定與公開頁面強制規則。

### 網站圖示

全站設定可選瀏覽器圖示並啟用多尺寸 PNG、Apple Touch Icon、Manifest、Safari mask icon 與 theme-color。SVG／ICO 須通過安全與格式檢查；停用平台時不輸出無效引用。這些設定不提供 Service Worker 或離線 PWA。

## 5. Step 4：加入圖片或影片

1. 在 Studio「媒體庫」按「上傳媒體」，於彈窗選一個原始檔案，可先檢視本機圖片／影片預覽、填寫顯示名稱，再上傳。等待實際格式／尺寸檢查通過。
2. 媒體以縮圖網格顯示；已處理影片顯示 Poster，尚未處理的素材標示「等待處理」。點縮圖開啟「媒體設定與引用」彈窗，在同一處查看資訊、保存設定，再按「處理媒體」。系統依圖片／影片自動採用既定處理規則，不需選擇轉碼參數。
3. 留在彈窗查看處理進度，或到「網站更新與工作」點該筆紀錄開啟「工作詳細資料」。完成前 `asset` 為 `null`，不提供尚不存在的輸出引用。完成後在媒體彈窗填寫此次引用的 Alt，按「複製媒體 HTML」貼入正文；Alt 不會自動成為其他引用的替代文字。
4. 文章設定的「精選圖片」及「OG Image」開啟選圖彈窗。先搜尋或換頁找圖片，同一張圖的多個尺寸只顯示一張卡片；點卡片後，從「選擇圖片尺寸」選實際解析度，再按「使用這個尺寸」。可用「返回圖片列表」重新選圖。精選圖片只列圖片，不列影片或影片封面；OG Image 與全站分享圖仍可選影片 Poster。
5. 精選圖片建議使用1280 × 720以上、16:9的橫式圖片；OG Image／全站分享圖建議1200 × 630。一般正文圖片保留原比例；分享圖另提供 1200 × 630 裁切或留白變體，依用途選取，避免與正文 srcset 混用。選圖彈窗內可「上傳新媒體」，或先處理尚未完成的媒體，之後接續選尺寸，不需離開文章。精選圖選「不使用精選圖片」保存 `null`；「精選圖片 Alt」另行填寫。
6. 影片可設定「Poster 秒數」，必須 `0 ≤ t < 實際片長`；留白時介面會依片長顯示目前預設要求秒數，實際畫面以可用影格為準。讀取片長前會明示尚無法確定，這個提示不會自動填入或保存設定。修改顯示名稱或 Poster 設定後先「保存媒體設定」，再重新「處理媒體」。已選圖片若不存在、設定改變而尚未重處理，或讀取失敗，介面保留原值並顯示問題，不會自動替換或清空。

| 項目                 | 保存／引用位置                                                   |
| -------------------- | ---------------------------------------------------------------- |
| 原始檔               | `media/source/<UUID>/original.<ext>`，同目錄 `meta.json`；不公開 |
| 衍生 cache／完成紀錄 | `.alfred/` 私有資料；不手工搬進 dist                             |
| 圖片公開引用         | `/media/<UUID>/image.webp`、實際存在的 `image-<寬度>.webp`       |
| 影片公開引用         | `/media/<UUID>/video.webm`、`poster.webp`                        |
| 正式產物             | `dist/media/<UUID>/`，由 Build 複製實際可達變體                  |

圖片接受 JPEG／PNG／WebP／AVIF 靜態圖，最多 25 MiB、40 MP、單邊 12,000，拒絕動畫圖；另支援通過專用安全、格式與容量檢查的 SVG／ICO。SVG 不接受 script、外部資源或其他不安全內容；不要把它當成可執行的 HTML 上傳。影片接受 MP4／MOV／WebM，最多 512 MiB、600 秒、60 fps、8.3 MP、單邊 4096，必須有可解碼影像軌。系統採固定圖片、圖示與 VP9 WebM 處理規則，不接受任意轉碼命令。

正式 HTML 使用媒體庫提供的 `src`／`srcset`／尺寸／poster；預覽內部才映射成受控 API URL。不要把 `/api/v1/media/files/...` 貼回文章，或直接引用 `media/source`、`.alfred`。缺尺寸時 Core 可依實際產物補值，但 `alt` 由作者決定。

既有圖片引用若是失效路徑，或精選圖舊值為影片封面，介面會保留原值並提醒作者明確改選，不會自動清空文章屬性。

只有 published 文章、網站設定及固定頁 `mediaRefs` 可達的資源會進 dist；只被 draft 引用的媒體不輸出。刪除媒體前會檢查草稿及已發布內容等引用，有引用回 409。先移除引用，再刪除來源；媒體刪除進 trash，可到「衝突與復原」處理。

## 6. Step 5：預覽與保存

Studio 在編輯後約 300 ms 更新 iframe 預覽，與正式網站共用 ArticlePage／CSS／TOC，顯示目前緩衝內容的診斷。1280px（含）以下需切到「預覽」頁籤查看，切換期間緩衝仍保留。

- 模擬裝置可選「桌機」1200 × 800、「平板」768 × 1024、「手機」390 × 844。選擇會改變預覽內頁的實際寬度，能檢查對應的響應式排版。
- 「預覽縮放」可選「符合區域」、50%、75%或100%。符合區域會把所選裝置完整縮入可用寬度；100%超出區域時可在預覽區捲動。畫面同時顯示模擬尺寸與實際縮放比例。
- 「放大預覽」開啟較大的預覽彈窗，可繼續切換裝置與縮放；關閉不影響文章內容。

裝置與縮放只調整工作室顯示，不會改寫正文、圖片尺寸或公開版型。預覽不寫來源、不執行正式 Build，也不更新 dist。每個編輯器保留最新預覽，10 分鐘過期或服務重啟後重新產生。

按「建立草稿」／「保存目前內容」或 Ctrl/Cmd+S 才寫入來源。保存成功才清除未保存狀態；發布失敗會保留緩衝與原磁碟版本。離開頁面有未保存內容時先確認是否捨棄。

IDE 編輯完後先執行：

```bash
docker compose exec app pnpm validate:content
```

這會檢查目前來源、路由與真實媒體，回報安全診斷與來源 revision，不產生根 dist。固定頁 HTML 最終錨點等輸出檢查仍須由正式 Build 完成。合法未完成草稿不因缺正文或語意未完成而擋下公開 Build；壞 JSON、未知 status 或缺 meta 無法安全辨識狀態，仍會失敗。

若 Studio 保存回 412，保留未保存版本，使用衝突介面比較「開始編輯時／尚未保存／已保存版本」後合併或重新載入。不要盲目重送舊版本。Article ETag 包括實際 diagnostics；即使正文未變，分類設定使診斷改變也可能回 412。媒體處理完成令 asset 改變時，媒體 ETag 也會更新。

## 7. Step 6：發布或撤回，然後成功 Build

1. 解決發布診斷，確認日期、分類、Tag、SEO description、媒體與連結。
2. Studio 按「發布目前內容」，確認完整候選及日期；已發布文章按「保存目前內容」保留發布狀態。IDE 則明確設定 `status`。
3. 前往「網站更新與工作」按「更新網站」，從工作表點選該筆紀錄，於「工作詳細資料」彈窗追蹤階段、進度、診斷與結果；需要時取消或按「以最新保存的內容重試」。也可在終端執行下列命令。
4. 成功後開啟 `4322` 的 dist 預覽，檢查文章、分類／Tag 分頁、RSS、Sitemap 與搜尋。

```bash
docker compose exec app pnpm validate:content
docker compose exec app pnpm build
```

`pnpm build` 是唯一正式建置入口，會建立一致來源快照、離線依賴、執行 Core／媒體／Astro、檢查完整產物後才切換根 dist。不要用裸 `astro build` 取代它。Build 期間來源改變會拒絕提升，不輸出混合版本。

Docker app 或原生 `pnpm start` 已啟動 `4322` 的網站預覽，不必再執行另一個 preview；成功 Build 後重新整理即可看見新版。獨立執行的 `pnpm preview` 同樣只服務最近成功的 dist，沒有成功產物或產物需要復原時明確失敗。Astro `4321` 是開發呈現，不能替代正式產物驗收。

在「網站更新與工作」的「目前網站版本」查看網站狀態；它以 `GET /api/v1/artifacts/current` 核對真正安裝的 dist，不以最近成功 Job 代替。目前沒有 dist、來源證據未知、待復原及來源已變更會分別顯示。只有最新讀取成功、產物 ready 且已確認的 snapshotRevision 等於目前 workspace.revision，才表示同步；API 讀取失敗不會拿舊資料宣稱同步。

若到「衝突與復原」把 B 產物還原為較舊的 A，B Job 仍保留歷史成功紀錄，但當前產物應顯示 A。來源仍是 B 時須重新 Build 才同步。keep-current 接受外部版本後，若無可靠來源證據會顯示未知；不能只因檔案存在或與某次歷史輸出相同就視為最新。

撤回：按「撤回為草稿」保存目前完整內容，再成功 Build，既有公開 HTML／列表／feeds 才會移除。刪除：文章列表確認刪除後進私有 trash，再成功 Build 更新公開輸出。`status` 改變或來源刪除本身不等於 dist 已更新。

修改已發布文章時，作者自行決定並填寫 `updatedAt`；Build 不更改日期。修改 slug／分類會改公開 URL，不產生自動 redirect；同步修正站內連結後再 Build。

分類遷移不會重寫正文舊 URL。遷移成功後回到「文章」，有連結、HTML 或媒體語意錯誤的文章仍列出真實診斷，可逐篇開啟修復。每次 Published 保存必須清除本篇全部錯誤，不得產生或改變其他文章的錯誤；只有未修改其他來源原已存在的相同錯誤可暫時原樣保留，讓多篇舊連結能逐篇修完。全站錯誤不能豁免；正式 Build 仍要求全站零 error。每修完一篇，重新開啟下一篇取得最新版本。壞 JSON、未知 status、缺 HTML／meta 配對或超限仍回422；symlink 依安全契約回409，不會吞錯後列成合法文章。先依診斷用 IDE 修復結構。

## 8. Step 7：處理失敗、取消與復原

| 狀況                                | 操作與結果                                                                                                                                                                 |
| ----------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 422／內容檢查失敗                   | 依欄位、articleId、行列診斷修正；原來源或舊 dist 保留                                                                                                                      |
| 409 IDE 模式                        | 結束 IDE 保存後切回 Studio，重新取得資料再操作                                                                                                                             |
| 412 舊版本                          | 比較三版本，重新載入或合併；不要強制覆蓋                                                                                                                                   |
| 請求回應遺失                        | Studio 沿用原 Idempotency-Key 查詢／重送；不要另建第二篇或第二個工作                                                                                                       |
| 工作 failed／cancelled／interrupted | 查看安全錯誤；使用重試建立新工作。媒體採最新來源，分類改名重新預覽並確認影響                                                                                               |
| 取消工作                            | 等待實際 worker／FFmpeg 結束；已提交完成的產物不能取消，回 409 並維持成功                                                                                                  |
| 工作區 recovery-required            | 一般啟動受阻時先依README啟動repair模式，再進「衝突與復原」，比對 base／current／prepared 及額外保留版本；明確選擇保留目前、還原備份或套用候選。未解前一般保存及 Build 暫停 |
| 刪除後需還原                        | 選 trash 的「從垃圾桶還原」；目標有任何同名新資料均 409，不能直接覆蓋                                                                                                      |
| 本輪 Build 失敗                     | 舊成功 dist 繼續可用；畫面上的失敗狀態不代表舊產物已消失                                                                                                                   |

普通成功保存的歷史備份為 `available`，可比較及還原，不會把工作區標成待復原；未知衝突才是 `pending`。備份至少保留 7 天及最近 20 筆，未解紀錄不自動清理。trash 保留 30 天；永久清除必須另行明確確認。不要手工刪除 `.alfred` 來排除衝突。

在「衝突與復原」點紀錄名稱或「比較版本」，開啟「復原比較」彈窗；從「比較資源」逐一查看原始備份、目前內容、準備版本及額外保留版本，必要時下載原文，再選擇該紀錄提供的決策並確認。比較視窗中的 HTML 僅顯示原文，不執行內容；若比較期間版本已變動，先「載入最新比較版本」再判斷，不能沿用舊比較結果強制覆蓋。

## 9. 程式與協定入口

| 入口                                                             | 責任                                                                       |
| ---------------------------------------------------------------- | -------------------------------------------------------------------------- |
| `packages/core/src/schemas/content.ts`、`schemas/common.ts`      | 唯一 metadata／日期／大小契約                                              |
| `packages/core/src/html/`、`content/`、`routing/`、`seo/`        | HTML、TOC、發布模型、路由與 SEO                                            |
| `packages/ui/src/article/ArticlePage.tsx`、`TableOfContents.tsx` | 共用文章結構與目錄                                                         |
| `packages/ui/src/styles/index.css`                               | 共用樣式來源；公開匯入 `@foliohaven/ui/styles.css`                        |
| `site/src/pages/[...article].astro`                              | 讀建置用私有 render context、列舉路由、掛載 React；不直接混讀 live content |
| `site/src/layouts/BaseLayout.astro`、`components/SeoHead.astro`  | Document、共用 Header／Footer 及 SEO                                       |
| `studio/src/ArticleEditor.tsx`、`MediaView.tsx`、`JobsView.tsx`  | 本機編輯及工作操作                                                         |
| `server/src/http/`、`content/`、`media/`、`jobs/`                | 受控 API、保存、媒體與持久工作                                             |

API 使用同源 `/api/v1`。建立文章／媒體／工作帶 UUID Idempotency-Key，保存既有文章帶精確 strong If-Match；缺少回 428、過期回 412。相同 key／payload 在 7 天期限內重送原始成功 status／body／ETag／Location，GET 才讀取最新狀態。工作原始 202 始終是建立當時的 queued 快照。

媒體 Node 內部 `inputRevision` 僅追原檔及 metadata raw 版本，與 HTTP representation ETag 分開；UI 不送或保存這個內部欄位。文章 HTTP 資源包含 `{id,contentHtml,meta,diagnostics}`，寫入只送 `{contentHtml,meta}`，不能把診斷或 ID 回寫進 metadata。

架構與 API 邊界見[主規格](<全靜態部落格系統 — 需求與技術架構規格 v1.0.md>)；固定頁面開發見[一般獨立頁面建立流程](一般獨立頁面建立流程.md)，執行與備份方式見[README](../../README.md)。
